Phase 2 社交层 预计工期 10–12 周
好友系统
玩家互加好友、查看好友在线状态，排行榜支持按好友范围过滤。社交关系是小游戏留存的核心驱动，当前平台完全缺失这一层。
优先级：高 工期 ~3 周 新模块
核心需求
  • 发起 / 接受 / 拒绝 / 撤回好友请求；双向确认后才建立好友关系
  • 好友列表返回每人在线状态（基于 WebSocket 心跳，精度 30 s）
  • 排行榜接口新增 ?scope=friends，仅返回好友范围 TopN
  • 好友数上限可在控制台按游戏配置（默认 200）
  • 屏蔽：屏蔽后对方无法发请求，WS 房间消息对其不可见
API 接口
POST /v1/friends/request{"target_player_id"} 发送好友请求
POST /v1/friends/accept{"request_id"} 接受
POST /v1/friends/decline{"request_id"} 拒绝 / 撤回
GET /v1/friends好友列表（含在线状态）
GET /v1/friends/requests待处理请求（发出 + 收到）
DELETE /v1/friends/{player_id}删除好友
POST /v1/friends/block{"target_player_id"} 屏蔽
暂不做：好友私信（WS 频道后续复用）；跨游戏好友关系（通行证层后续考虑）
成就系统
控制台定义成就，服务端（云函数或管理 API）触发解锁，客户端查询。成就是最普遍的留存机制之一，实现成本低、驱动回访效果强。
优先级：高 工期 ~2 周 新模块
核心需求
  • 成就定义：名称、描述、图标 URL、稀有度（common / rare / epic / legendary）、隐藏标记
  • 即时型（一次触发解锁）和进度型（progress / target，达到 target 自动解锁）
  • 服务端解锁接口幂等：重复调用不报错，返回已解锁时间
  • 客户端查：已解锁列表（含时间）；全部成就列表（隐藏成就未解锁时不暴露名称和描述）
  • WebHook 新增 achievement.unlocked 事件
API 接口
GET /v1/achievements全部成就列表（含我的解锁状态）
GET /v1/achievements/unlocked我的已解锁列表
POST /admin/api/games/{id}/achievements创建成就定义
PUT /admin/api/achievements/{aid}编辑定义
DELETE /admin/api/achievements/{aid}删除（未解锁的才能删）
POST /admin/api/achievements/{aid}/unlock{"player_id","progress"?} 服务端解锁
暂不做：成就积分商城；客户端自报解锁（必须服务端触发，防作弊）
服务器公告
控制台发布全服公告，客户端轮询拉取。用于版本更新提示、活动通知、维护通知等运营场景，是最轻量的运营触达手段。
优先级：中 工期 ~1 周 新模块
核心需求
  • 公告字段：标题、正文（Markdown）、重要性（info / warning / critical）、有效期
  • 客户端用 ?after_id= 增量拉取，减少重复传输
  • 可定向：全服 或 按 platform/channel 过滤
  • 控制台列表管理（发布 / 下架 / 预览）
API 接口
GET /v1/apps/{app_id}/announcements?after_id= 增量拉取（无需令牌）
POST /admin/api/games/{id}/announcements发布公告
PUT/DELETE /admin/api/announcements/{aid}编辑 / 下架
暂不做：Push 通知推送（需接 APNs/FCM，Phase 4+ 再评估）
Phase 3 运营工具 预计工期 8–10 周
虚拟货币
每款游戏可定义多种货币（如金币、钻石），服务端发放与消费，带幂等流水账本。为后续商店、邮件奖励、成就奖励提供统一的资产层。
优先级：高 工期 ~3 周 新模块
核心需求
  • 控制台定义货币种类（name, display_name, icon_url）；每游戏最多 8 种
  • 发放接口（管理 API + 云函数 mc.currency.grant）：幂等，带业务流水号 idempotency_key
  • 消费接口：原子扣减，余额不足返回 402；同样幂等
  • 查询：玩家余额列表；账本明细分页（来源、时间、备注）
  • 控制台可查看任意玩家余额和流水，支持人工补偿
API 接口
GET /v1/currency我的各货币余额
GET /v1/currency/{cid}/ledger我的流水明细（分页）
POST /admin/api/games/{id}/currency/{cid}/grant{"player_id","amount","idempotency_key","note"?}
POST /v1/currency/{cid}/spend{"amount","idempotency_key","note"?} 消费（玩家令牌）
POST/GET /admin/api/games/{id}/currencies货币种类 CRUD
暂不做：真实支付接入；货币交易所；货币有效期
游戏内邮件 / 奖励发放
控制台向玩家发送系统邮件，可附带货币奖励。用于活动补偿、全服福利、定向奖励，比直接调 grant 接口多了可审计的操作记录和玩家主动领取的体验。
优先级：中 工期 ~2 周 新模块
核心需求
  • 发送方式：全服广播 或 按 player_id 列表精准投递（最多 1000 条/次）
  • 邮件可携带货币奖励（多种货币）；玩家领取时原子发放，幂等
  • 邮件有效期（默认 30 天），过期未领则作废
  • 客户端查收件箱（未读数角标）、标记已读、领取附件；一次性领取
  • 控制台可查看邮件投递记录和领取率
API 接口
GET /v1/mailbox收件箱列表（?unread_only=true）
POST /v1/mailbox/{mid}/claim领取附件奖励
POST /v1/mailbox/{mid}/read标记已读
POST /admin/api/games/{id}/mail{"title","body","recipients","rewards"?,"expires_in"?}
GET /admin/api/games/{id}/mail邮件列表 + 领取率统计
暂不做：玩家互发邮件；邮件附件携带道具（道具系统未建）
留存率与漏斗统计
在现有 DAU / 登录 / 新增基础上补充 D1/D7/D30 留存率和注册漏斗，帮助开发者判断内容质量和回访能力。无需客户端接入，全部基于已有登录数据计算。
优先级：中 工期 ~1.5 周
核心需求
  • D1 / D7 / D30 留存率：以注册日为基准，次日 / 第 7 日 / 第 30 日回访比例
  • 注册漏斗：注册量 → 首次登录 → 7 天内再次登录
  • 统计接口新增 ?metric=retention 参数；控制台「统计」页新增留存折线图
  • 计算任务每日凌晨跑一次（延用现有 stats worker），结果写 Postgres 日表
API 接口
GET /admin/api/games/{id}/stats/retention?days=30 D1/D7/D30 留存率时序
GET /admin/api/games/{id}/stats/funnel?days=30 注册漏斗数据
暂不做：自定义事件漏斗；付费转化漏斗
玩家管理增强（封禁）
控制台封禁 / 解禁玩家，封禁后已签发的 JWT 立即失效，封禁期内登录请求被拒绝。现有管理页仅能查看玩家数据，缺少处置能力。
优先级：中 工期 ~1 周
核心需求
  • 封禁字段：原因（必填）、时长（永久 / 固定时长）、操作者
  • 封禁立即生效：黑名单写 Redis（TTL = 封禁时长），鉴权中间件复查
  • 封禁玩家登录时返回 403 player_banned，附带解封时间和原因
  • 控制台封禁记录列表，支持解禁操作
  • 封禁 / 解禁触发 WebHook 事件 player.banned / player.unbanned
API 接口
POST /admin/api/players/{pid}/ban{"reason","duration_secs"?} 封禁（0=永久）
POST /admin/api/players/{pid}/unban解封
GET /admin/api/games/{id}/bans封禁记录列表
暂不做：按 IP 封禁（IP 变化快，误伤率高，不建议）；申诉流程
Phase 4 平台扩展 预计工期 10–12 周
官方 JavaScript / TypeScript SDK
封装全部玩家 API 和 WebSocket，提供类型安全的接口，浏览器与 Node.js 双环境支持，发布到 npm。降低接入成本是扩大用户群的关键杠杆。
优先级：高 工期 ~4 周 独立仓库
核心需求
  • 完整覆盖：认证、存档、排行榜、成就、好友、货币、邮件、公告、云函数调用
  • WebSocket 客户端：自动重连（指数退避）、心跳维持、事件订阅 API
  • TypeScript 类型定义内置，零额外依赖
  • ESM + CJS 双格式打包；浏览器直接 <script type="module"> 引入
  • README 快速上手示例 + API 文档站
示例用法
const mc = new Zekumo({ appId: "zk_xxx", baseUrl: "https://api.example.com" });
await mc.auth.loginAsGuest({ deviceId });
await mc.playerData.set("save1", { level: 3 });
mc.realtime.on("room.state", ({ playerId, state }) => updatePlayer(playerId, state));
暂不做：Unity / Godot SDK（优先 JS 验证接口设计后再扩展）
游戏级 KV REST API
mc.kv 目前仅在云函数内可用。将其暴露为独立 REST 接口后，游戏服务端可直接读写游戏级配置（如活动开关、全局排名门槛），而无需通过云函数中转。
优先级：中 工期 ~1 周
核心需求
  • 命名空间隔离：每款游戏独立，key 格式 {namespace}/{key}
  • 读权限：玩家令牌可读公开命名空间；写权限：仅服务端（app_secret 签名）
  • 值上限 64 KB；可选 TTL（到期自动删除）
  • 列出命名空间下所有 key（分页）
API 接口
GET /v1/kv/{namespace}/{key}读取（玩家令牌）
PUT /v1/kv/{namespace}/{key}写入（app_secret，body = 任意 JSON）
DELETE /v1/kv/{namespace}/{key}删除（app_secret）
GET /v1/kv/{namespace}列出 key（玩家令牌，分页）
暂不做：条件写（compare-and-swap）；跨游戏共享命名空间
WebSocket 水平扩展
当前房间状态存在单实例内存，多实例部署时同一房间的玩家必须连同一实例。通过 Redis Pub/Sub 做跨实例消息分发，解除这一约束，对外接口零变更。
优先级：低（单实例够用时可推迟） 工期 ~3 周
核心需求
  • 房间元数据写 Redis（成员列表、房主、meta），从内存移除
  • 消息广播走 Redis Pub/Sub channel room:{room_id}；每个实例订阅并转发给本地连接
  • 同一玩家新连接顶掉旧连接时需跨实例通知（Pub/Sub 发 kick 事件）
  • Redis 断连时优雅降级：停止接受新 WS 连接，已有连接维持（本地广播继续，跨实例不保证）
  • 对外 API / WS 消息格式零变更，客户端无感
暂不做：WebRTC 信令中继；房间持久化（服务重启房间消失属预期）
数据导出
控制台触发玩家数据异步导出，生成 JSON / CSV 文件后提供下载链接。满足 GDPR 等法规的数据可携带（data portability）要求，也便于开发者做离线分析。
优先级：低 工期 ~2 周
核心需求
  • 导出范围：全部玩家 / 单个玩家；导出内容：档案、存档、货币流水、成就
  • 异步任务：提交后返回 job_id，轮询状态；完成后生成预签名下载 URL（24 小时有效）
  • 格式：JSON（嵌套结构）或 CSV（扁平化，多表分 zip）
  • 导出文件存在现有 storage driver（local / S3），复用上传签名逻辑
  • 控制台可查看导出历史和下载链接
API 接口
POST /admin/api/games/{id}/exports{"format","scope","player_id"?} 提交导出任务
GET /admin/api/exports/{job_id}查询进度 + 下载 URL
GET /admin/api/games/{id}/exports导出历史列表
暂不做：实时流式导出；玩家自助下载（需做独立授权页）
