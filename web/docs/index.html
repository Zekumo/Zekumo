01 / QUICKSTART

登录、存档、查询

先在控制台创建游戏，替换部署地址和 App ID。示例不保存管理员或玩家令牌到文档页面。

import { Zekumo } from 'zekumo-sdk';
const game = new Zekumo({
  appId: 'YOUR_APP_ID',
  baseUrl: 'https://your-game-server.example'
});
await game.auth.loginAsGuest({ deviceId: 'stable-device-id' });
await game.playerData.set('save', { level: 1 });
const save = await game.playerData.get('save');
const config = await game.kv.get('public', 'event');

浏览器/Node 的安装与 ESM/CJS 用法参见 TypeScript SDK；Go 接入参见 Go SDK。

02 / AUTHORITY

谁可以调用什么

玩家令牌

Authorization: Bearer <player JWT>。游戏身份由令牌决定，不能用请求字段切换游戏。对局记录只有参与者可读，玩家不能写入结果。

租户管理

管理员 JWT + X-Zekumo-Workspace-ID。viewer 只读，editor 管理内容，admin 管理成员，owner 处理受限操作。每个路由独立校验目标资源归属。

服务器签名

KV 写入使用 X-Zekumo-App-Id、X-Zekumo-Timestamp 和 HMAC-SHA256 签名。App Secret 不应出现在游戏客户端、公开函数输出或日志中。

管理登录、身份查询和工作区发现不要求工作区头。账户令牌、OAuth 令牌与玩家/管理员令牌是不同角色，不能混用。

KV HMAC 输入格式
signature = "sha256=" + hex(HMAC_SHA256(app_secret,
  timestamp + "." + METHOD + "." + URL_PATH + "." + raw_body))

时间戳为 Unix 秒，允许前后 5 分钟。签名使用原始 JSON 字节与实际 URL 路径；查询参数不在签名输入中。不要把密钥发给文档页面。

03 / GAME FLOWS

把功能连成一条线

云函数安全发布

保存共享草稿 → 用可选同游戏玩家测试 → 校验两份修订号后发布。每个函数保留最近 50 个版本，可恢复为新版本。测试草稿会操作真实游戏数据。

定时计划存入 PostgreSQL，副本共享调度间隔。调度先认领后执行，进程崩溃不会自动重试该间隔。

匹配与房间会话

match.join → match.found → room.ready → 房主 room.start → room.finish。匹配票据 120 秒过期，单游戏最多 128 人排队。先订阅事件，再加入队列。

房间与票据是进程内状态，重启/断线不恢复。跨实例 Redis 房间尚未实现；这不是权威竞技模拟服务器。

持久对局与奖励

可信云函数 mc.matches.create/complete/cancel 或管理 API 写入；客户端 matches.list/get 只读。结果对所有参与者可见，终态不可更改。

mc.currency.grant 使用业务幂等键；mc.achievements.unlock/progress 写入成就账本。结果和奖励没有跨服务原子事务，函数必须验证玩法证据。

存档与配置

玩家存档支持修订号与条件写，冲突需重新读取。游戏配置 KV 支持 64 KiB JSON、命名空间和 TTL；控制台可以管理公开与服务端配置。

public 和 public_ 前缀对玩家可读。KV 仍为最后写入覆盖，不提供 CAS。

好友与屏蔽

好友双向确认后建立关系。屏蔽清除好友与请求，阻止新请求并过滤发给屏蔽者的房间消息/状态。解除不自动恢复好友关系。

房间成员身份仍可见；这不是全局匿名或历史消息删除。

运营与分发

公告支持有效期、平台与渠道；邮件支持原子领取货币奖励；封禁、统计、异步导出与版本灰度分发有各自管理接口。

上线前完成部署检查和完整回归。接口存在不等于已经通过生产负载验证。

TypeScript 匹配示例
await game.realtime.connect();
game.realtime.on('match.found', async ({ room }) => {
  await game.realtime.setReady(true);
  // 房主等待所有成员就绪后调用 startSession()
});
await game.realtime.joinMatchmaking('duel', 2);
// 不确定请求是否成功时读取状态，不要盲目重复发起
const status = await game.realtime.matchmakingStatus();
